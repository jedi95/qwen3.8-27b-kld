# Qwen3.8-27B Quantization KLD Campaign

Full-vocabulary, teacher-forced KL divergence and top-1 agreement measurement
of Qwen3.8-27B quantizations against the official BF16 checkpoint, on a
3x RTX PRO 6000 Blackwell 96 GB workstation, using a vLLM fork with EXL3
support (pinned commit in `configs/environment.lock`, `scripts/setup_env.sh`).

Methodology: `docs/METHODOLOGY.md` (adapted from the Local Inference Lab KLD
protocol). The estimand is
**end-to-end serving divergence** `KL(BF16 reference || candidate)` over the
frozen 2048-token WikiText-2 window. Qwen3.8-27B is dense
(`Qwen3_5ForConditionalGeneration`, GDN hybrid attention, no routed experts) —
no MoE route control applies.

## Layout

```
docs/METHODOLOGY.md            protocol, controls, acceptance rule, statistics
configs/models.yaml            reference + candidate registry (frozen revisions)
configs/environment.lock       exact public vllm/b12x commits of the runs
.env.example                   machine-local config template (venv path, GPU, …)
data/qwen38-kld-tokens-2048.json   frozen token window (sha256 in tokens.manifest.json)
scripts/setup_env.sh           clones pinned repos, builds venv + EXL3 ext, writes .env
scripts/reproduce.sh           ONE-SCRIPT end-to-end reproduction + verification
scripts/preflight_repos.py     registry gate: every pinned revision resolvable
                               with real weights on the hub (fail-closed)
scripts/pin_revisions.py       audit registry revision pins vs the live hub
scripts/kld_capture.py         per-operand full-vocab prompt-logit capture (vLLM in-process)
scripts/kld_compare.py         KL(B||Q) + JSD + top-1 comparator (fail-closed)
scripts/verify_repro.py        rerun-vs-committed-numbers verifier
scripts/run_campaign.sh        orchestrates ref floor probe + candidate sweep
captures/<label>/              raw [2047, 248044] fp32 logit safetensors (gitignored)
results/comparisons/           one summary.json per candidate (committed)
results/campaign.json          aggregated table (regenerated by run_campaign.sh)
```

## Reproducing these numbers

```bash
git clone <this repo> && cd qwen3.8-27b-kld
scripts/reproduce.sh
```

That single script: builds the frozen environment from
`configs/environment.lock` (public commits — vLLM fork at the
`feature/exl3-support` HEAD pinned in the lockfile, b12x at its
capture-time commit),
verifies the token window sha256, re-captures the BF16 reference + runtime
floor probe (acceptance gate: floor must be ≤ 1e-6), sweeps every registry
candidate with two fresh-process captures each, and verifies every number
against the committed `results/comparisons/` snapshot. Budget ~500 GB of
model downloads (pinned revisions) and many GPU-hours on one 96 GB-class
Blackwell GPU (SM120; TP=1 — this is the captured configuration).

To use an existing environment instead of `setup_env.sh`, `cp .env.example
.env` and edit `KLD_PY` / `KLD_GPU_IDS` / `KLD_TP`. The engine commit must
still match `configs/environment.lock` — the numbers are engine-specific and
the floor probe (docs/METHODOLOGY.md §6) catches drift.

Piecewise:

```bash
scripts/run_campaign.sh ref          # BF16 refs + floor probes
scripts/run_campaign.sh nvfp4-nvidia # one candidate
scripts/run_campaign.sh all          # full registry sweep + report
scripts/run_campaign.sh report       # rebuild results/campaign.json
```

Raw captures are ~2 GB each and never committed; every summary records input
sha256s so any number is reproducible from `captures/` while it exists.

`weights` = main-model weight bytes on disk (HF cache snapshot; excludes MTP
draft heads and runtime KV/activations — see `results/RESULTS.md` notes).
BF16 reference: 51.7 GiB. All rows except the two `lribeiro/Qwen3.8-27B-*Pessoa`
entries are bit-identical across repeat captures; those two are
nondeterministic on this engine (~4–8e-4 KLD run-to-run), so they report the
mean of 5 fresh-process captures (spread documented in `results/RESULTS.md`). `head KLD` = KL over the **sampler-reachable
head** of the reference distribution — the top_p=0.95 nucleus within top_k=20
of softmax(z/T), T=1.0 (the Qwen3.8-27B `generation_config.json` defaults),
both operands renormalized on that head (~8.4 entries average, max 20).
This is exactly the set of tokens that can influence deployed sampled output,
which is what QAD-style distillation targets; computed from the same raw
captures by `scripts/head_kld.py` (floor 0.0).

**Self-calibration control:** the plain (non-`SC_`) turboderp branches beat
the `SC_*` (self-calibrated) branches at every bit-rate on this window —
6.00: 0.00721 vs 0.00796; 5.00: 0.00952 vs 0.01380; 4.00: 0.01593 vs
0.02140; 3.00: 0.04539 vs 0.06948; 2.00: 0.16394 vs 0.22133 — at similar or
identical size. The runtime floor is 0.0 on both paths, so the penalty is in
the checkpoint weights, not the engine. For Qwen3.8 on EXL3, prefer the plain
branches or the independently-calibrated `malaiwah` K5K6-hydrated build
(0.00399, 20.1 GiB), which dominates the entire 5–6 bpw turboderp family at
fewer bits.

Runtime floor: BF16-vs-itself KLD = 0.0 exactly; the b12x BF16 LM-head vocab
projection is bit-identical to cuBLAS (KLD 0.0 nats, top-1 1.0 — the
reference is kernel-neutral). Isolating the FP4 GEMM (cutlass control vs
b12x): b12x moves KLD +0.0038 (unsloth), +0.0071 (qad), +0.0011 (nvidia) —
worse on all three; top-1 drops on unsloth/qad but improves on nvidia
(0.9072 → 0.9145). Full table + deviation notes in `results/RESULTS.md`.
Expectation anchors live in `docs/METHODOLOGY.md#anchors` —
**same-ladder only**, never cross-comparable with those numbers.
